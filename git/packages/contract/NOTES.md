# @infrawrench/git-contract

The JSON API of git.infrawrench.com as Effect `HttpApi` definitions. The worker serves them; the UI derives its client from them (`HttpApiClient.make(GitApi)` or one of the per-group APIs). It imports only `effect`, and `@infrawrench/client-core` for the name rules and the branch key (`src/names.ts` re-exports them: the app claims an organisation's namespace by the same list, and links to a branch page by the same key).

## Layout

- `src/http/`: `errors.ts` (one `Schema.Error` class per status, `{ error, code? }` on the wire), `annotations.ts` (the gates), `auth.ts` (the middleware tags and the services they provide, `withApiDefaults`).
- `src/schemas/`: every request and response shape, by subject. `git.ts` is the content the UI draws directly.
- `src/groups/`: the endpoints. `src/api.ts` assembles `GitApi` (everything) and the per-group APIs.
- `src/names.ts`, `src/urls.ts`: pure functions both sides use (name rules and the reserved list; `parseBranchKey`, `formatBranchKey` and `branchPagePath`; clone, raw, archive and sign-in paths; `MCP_PATH`, `OAUTH_PATHS` and `WELL_KNOWN_PATHS` for the MCP server and its authorization server, which are not `HttpApi` endpoints: MCP is JSON-RPC over one path, and OAuth's endpoints are forms and a page whose shapes the RFCs fix).
- `src/bots.ts`: the bot accounts (Claude, Cursor), re-exported from client-core (`git-bots.ts`, beside the name rules that keep their usernames), and `botUserRef`, the `UserRef` one is named by (`kind: "bot"`). `UserRef.kind` is absent for a person.
- `src/limits.ts`: the plan limits and the sentence that refuses one more private repository, re-exported from client-core (`git-forge.ts`), where the app's Settings > Git words the same numbers.

## Conventions

- **Paths.** Everything is under `/api`. Repository endpoints are under `/api/repos/:owner/:repo`. Refs and tree paths are query parameters (`?ref=&path=`), never path segments, because both contain slashes. The one exception is a branch page's key (`:branch`), which is one percent-encoded segment (`feature%2Fa`), because it names a page and not a ref to resolve. A commit in a path is a full or abbreviated id (`:sha`).
- **Pagination is a cursor.** `?cursor=&limit=` in, `{ items, nextCursor }` out (`Page(item)`, `PageQuery`). `nextCursor` is opaque and null on the last page. `limit` is 1 to 100, default 30. Issue and branch page lists add `counts: { open, closed }` for their tabs. Lists that are short by nature (labels, milestones, reviews, review threads, keys, tokens, workspaces) answer a named array without a cursor.
- **Errors.** `{ error: string, code?: string }`. `error` is a sentence for a person; `code` is one of `ERROR_CODES` when the UI should branch on it. A private repository the caller cannot read is a 404, never a 403. The 401 and 403 of `Authentication` and the 404 of `RepositoryAccess` are declared on the middleware, so an endpoint's `error` lists only what it adds (400, 409, 422, 402).
- **Gates are annotations**, enforced by the worker's middleware before the payload is decoded:
  - `RequiredAccess` (`read` | `triage` | `write` | `admin`): the least `repoAccess` on the repository in the path. Every repository endpoint has one.
  - `RequiresUser`: a signed-in person. Every write that only needs `read` also has it, so an anonymous reader of a public repository cannot comment.
  - `RequiredOrgPermission` (`git:admin`): on the organisation named by `:orgId`.
  - `AllowedWhenArchived`: see "Archived repositories" below.
  - `HandlerGate`: documents a rule only the handler can check (the comment's author, the branch page's author, `write` on the head repository). It never stands alone: `RequiresUser` is beside it.
  - `src/__tests__/api.test.ts` holds all of the above across every endpoint, plus unique method and path pairs. An endpoint that is open to anyone with no gate must be added to that test's `OPEN` set on purpose.
- **Middleware order.** Repository groups are `.middleware(RepositoryAccess).middleware(Authentication)`: the later one is the outer one, so `Authentication` runs first and provides `Caller`, which `RepositoryAccess` requires.
- **Archived repositories.** `repoAccess` is at most `read` on one, for everybody. An endpoint annotated `AllowedWhenArchived` is judged against the level the caller would have without that cap: `repositories.update` (which unarchives), `repositories.delete` and every `admin` read (the settings pages). `RepositoryViewer.canAdminister` is the same un-capped answer for the UI.
- **Names that shadow globals are avoided**: `FileBlob`, `GitTag`, `TreeListing`, `ThreadComment` rather than `Blob`, `Tag`, `Tree`, `Comment`.
- **Every exported schema has a type of the same name** (`export type Branch = typeof Branch.Type`), so the worker and the UI name a shape without `typeof X.Type`.
- **Numbers are `Schema.Finite`** (tsc-rs's `schemaNumber` diagnostic), integers `Schema.Int`.

## Decisions

- **A branch page is named by its branch** (`BranchKey`, `schemas/common.ts`; the pure helpers are client-core's `git-branch-key.ts`). A key is `[<owner>/<name>:]<branch>[~<n>]`: `feature/a` is that branch of the repository in the path; `bob/infra:feature/a` a branch of the fork `bob/infra` proposed here (`-:feature/a` once the fork is gone); `feature/a~2` the second page that name had, counted oldest first among the pages of the same base, head repository and head ref. The bare name is the open page for that head, or the newest when none is open, and the canonical key a page answers in `key` is bare when the bare name reaches it and `~n` otherwise. At most one page per head is open. In a web URL the key's slashes are path separators (`branchPagePath`).
- **Issues and branch pages share a thread.** One number sequence, and the comments, timeline, labels, assignees, milestone and lock of a branch page are served by the `issues` group with its number. `issues.get` answers 404 for a page's number, `branches.locate` (`/branch-pages/:number`) answers a page's key for its number (what `#12` in a comment needs) and 404 for an issue's. The number is the conversation's, never the page's name: no URL and no page shows it.
- **Diffs are paged by file** (`Diff.nextCursor`), with whole-diff `stats` on every page. A file over the size budget comes back with `tooLarge: true` and no hunks; `?path=` asks for that one file whatever its size. `commit` and `compare` answer the file list without hunks; `commitDiff`, `compareDiff` and `branches.files` answer hunks.
- **Diff lines carry both line numbers** and no prefix character. `noNewlineAtEnd` is only present (as `true`) on the line it applies to.
- **Tree listings carry `lastCommit` per entry when the walk fits its budget.** `lastCommitsComplete: false` means some are null; `treeLastCommits` fills them in. The UI should render the listing first and call it only then.
- **Review comments are served as threads** (`branches.listThreads`), anchored by `path`, `side` and `line` in the current diff, with `outdated` and the original position kept. A pending review's comments are only sent to their author (`ReviewComment.pending`). A comment and a thread have ids of their own, so editing, deleting and resolving them are at `/review-comments/:commentId` and `/review-threads/:threadId/resolve`, under the repository and not under a page.
- **Mergeability is one block** (`Mergeability`), on `branches.get` and alone on `branches.mergeability` for polling while `state` is `checking`. `blockers` is the whole list of reasons, each with a code; `branches.merge` refuses with the first as its `code`.
- **Every branch but the default one has a page**, opened by its first push. `branches.propose` (`POST /branch-pages`) opens the others: a fork's branch proposed to its parent (`headRepository`), or a branch pushed before pages were opened on push. 409 `branch_page_exists` when the head has an open page. Fields that named a page by number elsewhere name it by key: `Branch.page`, `Comparison.page`, `CommitDetail.branchPages`, `CiRun.branchPage`, `TerraformRun.branchPage`, `Mention.branch`.
- **Raw files and archives are not endpoints**: they stream bytes, so they are plain URLs (`rawPath`, `archivePath`). A ref in those paths is resolved greedily; the UI links by commit id where it has one.
- **Sign-in is not an endpoint** either (`AUTH_PATHS`). `session.me` never answers 401; it answers `user: null`.
- **CI is read-only here.** Retrying, cancelling and approving a run happen in the app (`CiRun.appUrl`), where `ci:approve` lives. The CI status lists repeat client-core's `ci.ts`; a status added there is added to `schemas/ci.ts`.
- **Terraform, with the runtime.** `terraform.listAccounts` is the picker of a workspace's accounts (the organisation's, for a person with `accounts:read`; empty otherwise). `terraform.createRun` starts a run by hand. `terraform.downloadStateVersion` answers the document as text (`write`: it holds secrets) and `terraform.restoreStateVersion` the new current version. `terraform.approveRun` is annotated `read` with `RequiresUser` and gated in its handler (a signed-in admin of the repository, or `ci:approve` in the organisation); `viewerCanApprove` on a waiting run tells the UI. `skipped` is a run status (a fork's proposed branch), and `terraform_run` a timeline item. A run's trigger is `branch` for a page's plan. A workspace's and a resource's `monthlyCost` is the last thirty days' spend as the caller may see it.
- **Terraform shapes follow the tables.** State documents are never served by this API (they hold secrets), only their metadata (`sha256`, not an MD5). Costs are null for callers who may not see costs in the app, and a run's cost change carries the monthly delta alone (`monthlyBefore` and `monthlyAfter` are null) until the totals are stored. A workspace's name is a URL segment and part of an R2 key: lowercase letters, digits, `-` and `_`. `forget` is an action beside `delete`: removed from state, not destroyed.
- **A name's availability is told to nobody its creation would not tell.** `repositoryLists.nameAvailability` answers for a namespace only to someone who may create there (the handler's gate, the same refusal `create` gives), and such a person can read every repository of the namespace; `repositories.renameAvailability` takes the `admin` that `rename` takes. Neither says more than the 409 of the write it stands in front of. A stranger gets the same 403 for a private repository's name as for a free one.
- **What a new repository starts as is on the session.** `SessionOrganization.defaultVisibility` (set in the app, Settings > Git), `privateRepositories` and `privateRepositoryRefusal` (the quota's own sentence, the one the 402 carries), and the same three for the person's own namespace under `Session.personal`.
- **The CI switch is the repository's.** `ci.settings` and `ci.updateSettings` take `admin` on the repository. `available` is false in a personal namespace, where the update answers 422 `ci_unavailable`. Whether runs start is still `ci.status`, which also reads the owner's plan. Secrets and variables are not here.
- **Token scopes are `repo:read` and `repo:write` only.** A token never reaches settings or credentials: `AccountGroup` is session only.

- **A person's work across repositories** (`schemas/workspace.ts`, `groups/workspace.ts`) is `/api/workspace`: `home`, `changes` and `mentions`, each for a signed-in person and none with a repository in its path. There is no list of requested reviews, because the schema has no such request: `review.inbox` is the branches with a version the viewer has not reviewed. `ChangeState` is a list's state and deliberately not `BranchPageStateName`: it reads nothing of the viewer and no checks. `SuggestionReason.kind` and `ActivityEvent.type` are closed lists a client switches on; a new one is a contract change.
- **Agent work review** (`schemas/review.ts`, `groups/review.ts`) is defined whole, ahead of the handlers: versions and their diffs, the branch page's state, the inbox, traces, findings and review runs, the merge override, instructions, the agent behind a branch, starting work, T3 Code environments and a repository's review settings. An endpoint the worker does not serve yet answers 503 `not_implemented` (`notImplemented`), after its gates.
  - Everything about one branch is under `/api/repos/:owner/:repo/branches/:branch`, beside the page itself. A version in a path is its number or `latest`. Traces are the exception (`/traces?branch=`): they are written to a branch that may not have a page, or exist, yet.
  - `agents.startWork` (`POST /work`) answers `{ page, branch, agent }`: the branch it made and its page, opened as a draft with the ask as its description.
  - `versions.diff` is one endpoint: `from` is `base` (the whole change), `previous`, a version's number, or `reviewed` (the viewer's last mark).
  - Fields added to shapes that existed are optional keys (`BranchPageSummary.latestVersion`, `ReviewThread.version` and `answeredInVersion`, `ReviewComment.version`, `Mergeability.findings`), so a client built before them still decodes. `MERGE_BLOCKERS` gained `must_fix_findings`.
  - Lists that grow on the server (`reviewerKind`, an agent identity's `kind`, `deliveredVia`) are strings with their known values documented.
  - `traces.record` is the one write annotated `read` without `RequiresUser`: a CI job's token has `read`, and the handler takes a person with `write` or the job. The contract test names it (`JOB_WRITES`).
  - `needsCode` on `TraceEntry` and `ReviewFinding` is required on the read shapes and an optional key on `TraceEntryCreate` and `FindingCreate`: the worker resolves it when the row is written (true with a line, false without; true with no file at all is stored false) and stores it, so a reader never applies the default itself. `MergedFinding` does not carry it: it is a summary with no body, linked to the page that has the finding whole.
  - The `t3` group is session only in the worker, and its OAuth redirect is a URL, not an endpoint (`AUTH_PATHS.t3Callback`).

## Not here yet

- Webhooks, notifications, releases, repository redirects after a rename, editing files in the browser, requested reviewers, reactions.
- An OpenAPI document is not published; `OpenApi.fromApi(GitApi)` builds one (the test checks that it does).
